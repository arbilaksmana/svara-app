GAPS AGAINST ACTUAL ACCESS PATHS (static mapping; plans to be captured after gate)
1. public_links.token_hash lookup: `SELECT * FROM public_links WHERE token_hash = ?` (server/routes/public.ts:216) has no token_hash index; the existing unique index is on raw `token`. Every public intro/consent/form/submit/receipt resolves this by sequential scan.
2. invitations.token_hash lookup: `SELECT * FROM invitations WHERE token_hash = ?` (server/routes/public.ts:212) has no token_hash index; existing unique index is on raw `token`. Every invitation path pays a sequential scan.
3. responses ordered pagination/export: `WHERE survey_id=? AND version_id=? ORDER BY submitted_at DESC LIMIT ? OFFSET ?` (server/routes/surveys.ts:795) and `ORDER BY submitted_at, id LIMIT ? OFFSET ?` (server/routes/integration.ts:81). Only single-column indexes on survey_id/version_id exist; no (version_id, submitted_at, id).
4. answers by option/question for summary: summary option counts filter `answers.option_id` and `answers.response_id IN (responses of version)`; answered counts filter `answers.question_id` + responses.version_id. No index on answers(option_id) or answers(question_id); current indexes are (response_id) and (response_id, question_code).
5. audit by organization: `WHERE organization_id=? ORDER BY at DESC, id DESC LIMIT ?` (server/routes/org.ts:298). ix_audit_at cannot filter organization; no (organization_id, at DESC).
6. surveys listing/order: accessibleSurveys filters owner_id/organization_id and orders by updated_at; no index on surveys(owner_id), surveys(organization_id), surveys(updated_at).
7. admin stats joins: perCreator joins accounts -> surveys on owner_id; perSurvey joins survey_versions and responses by survey_id; COUNT(DISTINCT) over the fan-out. No supporting index on surveys(owner_id).
8. integration_events/data_requests admin lists order by at/created_at DESC LIMIT 250; no indexes on those sort columns; acceptable only while tables are small.
9. question_options: no index on question_id (options are fetched by question_id per question in summary/public context); small table, low priority.
10. sessions: expiry index exists but no sweep deletes expired sessions; lazy delete only on access of that token.
